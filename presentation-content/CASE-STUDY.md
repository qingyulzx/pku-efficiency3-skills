# 案例研究：一场组会汇报的内容是怎么被决定的

> 对应题目：学术汇报内容组织（challenge-20870c35）
> demo 产物：本目录 [demo/](./demo/)（真实论文 arXiv:1706.03762 输入 → 组会版 deck + 大纲 + cut_log + result.json）

## 1. 人类经验是什么

研究生准备组会时，脑子里跑着一套没人写下来的规程：

- **听众是同组的人**——他们要方法细节、进度、下一步（合起来 ≥60% 篇幅），背景一页都嫌多；答辩则反过来：创新点、边界、对比优先；评审场合：结论先行，背景压到最少。
- **时长换页数**：10 分钟 ≈ 8±2 页；超页数时的砍法有优先级——先砍背景，再合并次要结果，核心结果永不砍；被砍的整页降级为 closing 后的备用页（问答时可能救场），而不是删除。
- **每个上页的数字，讲的人当场要能答出"哪张表第几行"**——答不出的数字不上页。

基础 Agent 的典型输出是「论文压缩一遍」：段落复制进页面，无听众意识、无取舍理由、数字无出处。

## 2. Skill 怎么编码这段经验

- **场景判据表**（SKILL.md Step 3，内联在使用点）：组会/答辩/评审三套页配比、叙事顺序、问答压力——来自真实汇报 craft，不是模板套话
- **砍页优先级 P0→P3 + cut_log**（Step 4）：每条取舍写理由（"cut 表 2 消融——页数预算 6 页，主结果优先"），机器可读、可抽查
- **数字纪律**：数字逐字（28.4 不写 ~28）、出处进该页 evidence、找不到出处不上页
- **四档证据强度**：direct / indirect / inferred / gap——诚实区分论文原文说的和讲者推断的

## 3. 增益怎么验证

相同论文输入的对照（平台即以 base-agent vs skill-agent 同案例对照计「使用增益」）：

| 维度 | 基础 Agent | 加载本 Skill |
|---|---|---|
| 每页主张 | 话题标签（"实验结果"） | 一句完整 claim（"同压缩率下形状误差低 38.2%"） |
| 证据 | 无 | 每页 ≥1 条逐字引文+页码定位（demo 大纲 12 条） |
| 取舍 | 静默 | 4 条决策带理由进 cut_log（demo） |
| 讲稿 | 复读页面文字 | 每页 speaker notes 讲稿 |
| 诚实度 | 不标注 | 1 个 gap 明确标注（demo） |
