# 三场景深度手册（组会 / 答辩 / 评审）

SKILL.md 的 Step 3 内联了速查判据表；本文件是展开版，只在需要深挖某一场景时读。
判据本身与速查表一致：**先看速查表定骨架，再按需来这里取细节**。

## 0. 通用硬规则（三场景共用）

1. **每页一句主张**：页面标题写成可讲出口的判断句（"注意力机制可完全替代循环结构"），
   而不是名词标签（"方法"）。名词标签的页面在评审眼里=没有信息。
2. **证据强度四档**（标注进 outline.evidence.strength 与 result.json）：
   - `direct`：源材料中有逐字对应的数据/结论（引文+定位可复核）。
   - `indirect`：由源材料中多处信息合并得出（列出所用定位）。
   - `inferred`：由我方外推（如跨场景类比），必须口头说明假设。
   - `gap`：材料没有支撑。页面保留主张但打 `[证据缺口]` 标注，绝不编数字。
3. **时长-页数预算表**（讲得从容的经验值，超了就砍）：

   | 时长 | 内容页（不含 backup） | 单页讲述 |
   |------|----------------------|----------|
   | 5 分钟 | ≤4 | 60–75 秒/页 |
   | 10 分钟 | 6–8 | 60–75 秒/页 |
   | 15 分钟 | 9–12 | 60–75 秒/页 |
   | 20 分钟 | 12–15 | 60–80 秒/页 |

   案例给了 `slide_count` 就以案例为准；两者冲突时**保页数上限、按砍页优先级砍**，
   并在 cut_log 记录冲突与处置。
4. **砍页优先级**：P0 主张+核心证据 → P1 背景铺垫/方法主干 → P2 扩展结果/次要消融
   → P3 礼节页/延伸展望。先砍 P3，同级里砍"删掉不影响主线闭环"的那页。
5. **讲稿不复读页面**：notes 写口语过渡句、数字读法（"3.5 个点"）、指图动作
   （"看左下这张表"），页面 bullets 是骨架，讲稿是血肉。
6. **图表绑定**：每张引用的图/表必须有 locator（文件+页码+编号）；图缺失时标
   `[图缺失]` 并在 backup 里放替代证据（表格化的数字），不放假图。

## 1. 组会（group_meeting）——讲方法与进度

**听众画像**：同方向研究者，懂术语，不知道你这三周做了什么；他们的目标是
判断"这活儿靠不靠谱、卡在哪、下一步值不值"。

**页配比参考**（8 页版）：进展回顾 1 / 问题定义 1 / **方法细节 3** /
**中间结果+问题 2** / **下一步计划+风险 1**。方法+进度+下一步 ≥ 60%。

**叙事顺序**："上次说到 X → 这次解决了/卡在 Y → 新证据 Z → 下一步 W"。
第一页就把进度坐标钉死，不要从 abstract 重新讲一遍。

**方法页要求**：公式留关键一步（截图或重排），标注"与上一版/基线的差异"；
组会听众会盯着细节问，**方法页 evidence 全部要 direct**。

**问答压力**：最常被问"为什么不用 <替代方案> / 这个结果稳不稳 / 下周能出什么"。
备 1 页 backup：替代方案对比表（从材料或文献定位里取，没有就标 gap）。

**完成标准**：散会后听众能复述"他卡在哪、下一步做什么"。

## 2. 答辩（defense）——讲创新点与边界

**听众画像**：评委跨方向，时间紧，先找漏洞再给分；他们要的是
"创新点是什么、边界在哪、和已有工作的差异有多硬"。

**页配比参考**（10 页版）：问题与意义 1.5 / **创新点声明 1** / **方法与证据 3** /
**对比与边界 2.5** / 结论与展望 1 / 致谢 0.5。创新+对比+边界 ≥ 50%。

**叙事顺序**："领域缺什么 → 我提出什么（一句话创新点声明，越早越好）→
证据链 → 与最强对手的正面对比 → 我承认的边界（主动说，别被问出来）"。

**创新点声明页**：一页只放一件事——"与已有工作相比，本工作的差异是 <一句>"，
evidence 用 direct 引文（通常在 Intro 的贡献列表或 Related Work 的对比句）。

**边界页**：主动列 2–3 条局限，每条配"因此我们未来/当前如何补救"。
主动承认的边界是加分项；被评委问出来的边界是扣分项。

**对比页**：和最强基线的表格对比，数字必须逐字来自源材料（direct）；
材料里没有对比数字就做 qualitative 对比并标 `inferred`，绝不造数字。

**问答压力**：最高。"这个创新点是不是就是 X 的特例""结果为什么不做显著性检验"
"泛化到 Y 场景会怎样"。backup 页备：推导细节、额外消融、失败案例。

**完成标准**：评委记住 1–2 个带证据的创新点，且挑不出"没想过"的漏洞。

## 3. 评审（review）——讲结论与证据强度

**听众画像**：基金/论文评审人，看几十份材料，注意力以分钟计；他们扫的是
"结论是什么、证据硬不硬、风险大不大、值不值这个资源"。

**页配比参考**（6–8 页版）：**结论先行 1**（第一页就给结论+证据强度）/
关键证据 2–3 / **风险与缓解 1** / 资源与产出 1 / 附录索引 1。

**叙事顺序**：结论先行（BLUF）。第一页 = 结论 + 最硬的一条证据 + 强度标注；
后面每页都在加固或限定这个结论。评审场景里"背景铺垫>1 页"是常见败笔。

**证据强度展示**：每页页脚标注本页结论的强度档（脚本自动从 evidence 汇总）；
结论页的表述必须与强度匹配——`direct` 才能说"我们证明了"，`indirect` 只能说
"数据一致地表明"，`inferred` 只能说"我们有理由预期"。

**风险页**：技术风险、数据风险、时间风险各 1 条，每条配缓解措施；
评审人对"知道自己在冒什么险"的团队信任度显著更高。

**问答压力**：书面追问为主。备"若被要求补充，最可能要什么数据"清单。

**完成标准**：评审人合上材料后能写出你的结论和它的强度。

## 4. 问答准备（qa_prep）通用模式

对每页问自己四个问题，能答的进 `qa`，答不了的进 `uncertainty`：
1. 机制追问：为什么这个方法会 work？（备 backup：机制图/推导）
2. 数据追问：数字怎么来的？样本量？对照设置？
3. 边界追问：什么情况下不 work？做过什么失败尝试？
4. 价值追问：so what？谁在乎这个结果？

口径一致性自检：notes 里的讲法、页面 bullets、qa 的回答，三处对同一数字/结论
的表述必须一字不差地同源（都指向同一个 locator）。
